# Use Cases — Воронки продаж (Funnel)

---

## UC-FUNNEL-01: Создать воронку

**Актор:** `admin`, `director`  
**API:** `POST /api/v1/funnels/`

### Предусловия
- Текущий пользователь имеет роль `admin` или `director`

### Порядок действий

1. Пользователь отправляет `name` воронки
2. Система проверяет роль (`admin` или `director`); если нет — `403`
3. Валидирует `name` (непустая строка, не длиннее 255 символов)
4. Создаёт запись `Funnel` с `is_deleted = false`
5. Устанавливает `created_at` и `updated_at`
6. Возвращает созданную воронку (`201 Created`)

### Что решает
Позволяет разделить разные процессы продаж по отдельным воронкам (например, «Продажа курсов» и «Корпоративные клиенты»). Каждая воронка имеет собственные этапы и независимые потоки лидов.

### Альтернативные сценарии
- **Нет прав:** `403 Forbidden`
- **Пустое или слишком длинное название:** `422`

### Постусловия
- Новая `Funnel` создана без этапов (этапы добавляются отдельно через `UC-STAGE-01`)

## UC-FUNNEL-02: Получить воронку

**Актор:** Любой аутентифицированный пользователь  
**API:** `GET /api/v1/funnels/{id}`

### Предусловия
- Пользователь аутентифицирован
- Воронка с указанным `id` существует и не удалена (`is_deleted = false`)

### Порядок действий

1. Система принимает `funnel_id` из URL
2. Загружает воронку из БД
3. Если не найдена или `is_deleted = true` — `404`
4. Возвращает данные воронки: `id`, `name`, `created_at`, `updated_at`

### Что решает
Базовая операция получения мета-данных воронки. Используется фронтендом при открытии Kanban-доски для отображения названия и навигации.

### Альтернативные сценарии
- **Воронка не найдена:** `404`
- **Воронка удалена:** `404`

### Постусловия
- Состояние системы не изменяется (read-only)

## UC-FUNNEL-03: Переименовать воронку

**Актор:** `admin`, `director`  
**API:** `PUT /api/v1/funnels/funnel_update/{id}`

### Предусловия
- Текущий пользователь — `admin` или `director`
- Воронка существует и не удалена

### Порядок действий

1. Пользователь отправляет новое `name`
2. Система проверяет роль; если нет — `403`
3. Загружает воронку по `id`; если не найдена — `404`
4. Валидирует новое `name`
5. Обновляет `Funnel.name`
6. Обновляет `updated_at`
7. Возвращает обновлённую воронку

### Что решает
Позволяет адаптировать названия воронок под изменившиеся бизнес-процессы без пересоздания. Переименование не затрагивает лиды, этапы и источники — все FK остаются валидными.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Воронка не найдена:** `404`
- **Невалидное имя:** `422`

### Постусловия
- `Funnel.name` обновлён
- `Funnel.updated_at` обновлён

## UC-FUNNEL-04: Удалить воронку (Soft Delete)

**Актор:** `admin`  
**API:** `DELETE /api/v1/funnels/{id}`

### Предусловия
- Текущий пользователь — `admin`
- Воронка существует и не удалена

### Порядок действий

1. Система проверяет роль (`admin`); если нет — `403`
2. Загружает воронку по `id`; если не найдена — `404`
3. Устанавливает `Funnel.is_deleted = true`
4. Обновляет `updated_at`
5. Возвращает `204 No Content`

### Что решает
Исключает воронку из активного использования, сохраняя исторические данные. Лиды, привязанные к удалённой воронке, остаются в БД и доступны в аналитике. Физического удаления нет — данные никогда не теряются.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Воронка не найдена:** `404`
- **Воронка уже удалена:** `404`

### Постусловия
- `Funnel.is_deleted = true`
- Воронка не отображается в списке активных воронок
- Все этапы воронки технически остаются в БД (каскадное удаление не происходит при soft delete)
- Существующие лиды по-прежнему ссылаются на воронку

## UC-FUNNEL-05: Список воронок

**Актор:** Любой аутентифицированный пользователь  
**API:** `GET /api/v1/funnels/` *(не задокументирован явно, но подразумевается)*

### Предусловия
- Пользователь аутентифицирован

### Порядок действий

1. Система запрашивает все воронки, где `is_deleted = false`
2. Сортирует по `created_at` (или `name`)
3. Возвращает список

### Что решает
Предоставляет список доступных воронок для Kanban-доски, создания лида вручную и настройки источников.

### Альтернативные сценарии
- **Нет воронок:** возвращает пустой список `[]`

### Постусловия
- Состояние системы не изменяется (read-only)
