# Use Cases — Значения кастомных полей (LeadCustomFieldValue)

---

## UC-FVAL-01: Установить значение кастомного поля лида

**Актор:** Назначенный пользователь, `sales_manager`, `director`, `admin`  
**API:** `PATCH /api/v1/leads/{lead_id}` *(в теле передаются `custom_values`)*  
*(или отдельный `POST /api/v1/leads/{lead_id}/custom-values`)*

### Предусловия
- Лид существует и не удалён
- `LeadCustomField` существует и не удалён
- Текущий пользователь имеет право редактировать лид
- `field_type` соответствует типу передаваемого значения

### Порядок действий

1. Пользователь передаёт массив значений: `[{ "custom_field_id": "uuid", "value": ... }]`
2. Система проверяет доступ к лиду; если нет — `403`
3. Загружает лид; если не найден — `404`
4. Для каждого значения в массиве:
   a. Загружает `LeadCustomField`; если не найден или удалён — `422`
   b. Определяет `field_type` поля
   c. **Для `text`:** сохраняет в `value_text`, остальные колонки = NULL
   d. **Для `number`:** сохраняет в `value_number` (NUMERIC), остальные = NULL
   e. **Для `date`:** сохраняет в `value_date` (DATE), остальные = NULL
   f. **Для `time`:** сохраняет в `value_time` (TIME), остальные = NULL
   g. **Для `boolean`:** сохраняет в `value_boolean`, остальные = NULL
   h. **Для `select_one`:** проверяет, что `enum_value` принадлежит данному полю; если нет — `422`; сохраняет в `enum_value`; гарантирует ONE запись на поле (upsert)
   i. **Для `select_many`:** проверяет каждый `enum_value`; создаёт отдельную строку на каждый выбранный вариант
5. Если значение для поля уже существует — **обновляет** (upsert); если нет — **создаёт**
6. Обновляет `updated_at` лида
7. Записывает `LeadHistory` (action `custom_field_updated`) для каждого изменённого поля
8. Возвращает обновлённый лид с кастомными значениями

### Что решает
Хранит специфичные для бизнеса данные лида: встречи, бюджеты, категории, предпочтения. Строгое разделение по колонкам (`value_text`, `value_number` и т.д.) обеспечивает типобезопасность и возможность фильтрации по числовым/датным диапазонам в будущем. Единая логика upsert упрощает работу фронтенда — не нужно различать «создание» и «обновление».

### Альтернативные сценарии
- **Нет прав:** `403`
- **Лид не найден:** `404`
- **`custom_field_id` не существует или удалён:** `422`
- **`enum_value` не принадлежит указанному полю:** `422`
- **Передан `number` для поля типа `text`:** `422`
- **Для `select_one` передано несколько значений:** `422`

### Постусловия
- `LeadCustomFieldValue` создан или обновлён
- `LeadHistory` содержит запись `custom_field_updated`
- `Lead.updated_at` обновлён

## UC-FVAL-02: Очистить значение кастомного поля лида

**Актор:** Назначенный пользователь, `sales_manager`, `director`, `admin`  
**API:** `PATCH /api/v1/leads/{lead_id}` *(передаётся `value: null` для поля)*  
*(или `DELETE /api/v1/leads/{lead_id}/custom-values/{custom_field_id}`)*

### Предусловия
- Лид существует и не удалён
- `LeadCustomFieldValue` для данного лида и поля существует
- Текущий пользователь имеет право редактировать лид

### Порядок действий

1. Пользователь передаёт `{ "custom_field_id": "uuid", "value": null }` или явный DELETE
2. Система проверяет доступ; если нет — `403`
3. Загружает лид; если не найден — `404`
4. Загружает `LeadCustomFieldValue` по `lead_id` и `custom_field_id`
5. Если записи нет — `404` (или тихо игнорирует — business decision)
6. Для `select_many` — удаляет все записи данного поля для данного лида
7. Для остальных типов — удаляет одну запись (или обнуляет значение)
8. Обновляет `updated_at` лида
9. Записывает `LeadHistory` (action `custom_field_updated`, `new_value = null`)
10. Возвращает `200 OK`

### Что решает
Позволяет убрать ошибочно введённое или устаревшее значение кастомного поля. При soft delete поля (`UC-FIELD-04`) значение сохраняется и доступно для аудита, но очистка через этот use case — это явное намерение пользователя удалить данные.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Лид не найден:** `404`
- **Значение не существует:** `404` или тихий `200`

### Постусловия
- `LeadCustomFieldValue` удалён физически (CASCADE по `lead_id`) или обнулён
- `LeadHistory` содержит запись `custom_field_updated`
