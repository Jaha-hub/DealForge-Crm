# Use Cases — Источники лидов (Source)

---

## UC-SOURCE-01: Создать источник

**Актор:** `admin`  
**API:** `POST /api/v1/source/`

### Предусловия
- Текущий пользователь — `admin`
- Для `webhook` и `public_form`: указанные `funnel_id` и `stage_id` существуют и активны

### Порядок действий

1. Пользователь отправляет: `name`, `source_type` (`manual` | `webhook` | `public_form`), и конфигурацию под тип
2. Система проверяет роль (`admin`); если нет — `403`
3. Валидирует `source_type`
4. **Если `webhook`:**
   - Проверяет наличие `funnel_id`, `stage_id`, `field_mapping` в `config`
   - Проверяет, что `stage_id` принадлежит `funnel_id` и имеет тип `initial`
   - Генерирует случайный `secret_token` (UUID или random-hex, 32+ символа)
   - Сохраняет токен в `config.secret_token`
5. **Если `public_form`:**
   - Проверяет `funnel_id`, `stage_id`, `visible_fields`
   - Проверяет, что `stage_id` принадлежит `funnel_id` и имеет тип `initial`
6. **Если `manual`:** `config = {}`
7. Создаёт `Source` с `is_active = true`, `is_deleted = false`
8. Возвращает созданный источник (`201 Created`)

### Что решает
Регистрирует новый канал поступления лидов. Разделение типов позволяет гибко подключать внешние системы (webhook), встраиваемые формы (public_form) и ручной ввод (manual) с независимыми настройками для каждого. Автоматическая генерация `secret_token` для webhook обеспечивает безопасность без ручной настройки.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Невалидный `source_type`:** `422`
- **`stage_id` не принадлежит `funnel_id`:** `422`
- **`stage_id` не является `initial`:** `422`

### Постусловия
- Новый `Source` создан и активен
- Для `webhook`: сгенерирован `secret_token`, доступен в ответе (и только сейчас — больше не отображается)
- Для `public_form`: форма доступна по URL `/forms/{source_id}`

## UC-SOURCE-02: Получить источник

**Актор:** Любой аутентифицированный пользователь  
**API:** `GET /api/v1/source/{id}`

### Предусловия
- Источник существует и не удалён

### Порядок действий

1. Система загружает источник по `id`
2. Если не найден или `is_deleted = true` — `404`
3. **Для `webhook`:** `secret_token` в ответе **скрыт** (возвращается маска или `***`) — токен показывается только при создании или регенерации
4. Возвращает данные источника

### Что решает
Позволяет просматривать конфигурацию источника для отладки и управления. Скрытие `secret_token` предотвращает его утечку через интерфейс просмотра.

### Альтернативные сценарии
- **Источник не найден:** `404`

### Постусловия
- Состояние не изменяется (read-only)

## UC-SOURCE-03: Обновить источник

**Актор:** `admin`  
**API:** `PUT /api/v1/source/{id}`

### Предусловия
- Текущий пользователь — `admin`
- Источник существует и не удалён

### Порядок действий

1. Пользователь отправляет обновляемые поля: `name`, `config` (частично или полностью)
2. Система проверяет роль; если нет — `403`
3. Загружает источник; если не найден — `404`
4. Валидирует обновляемые поля согласно типу источника
5. Если обновляется `funnel_id` или `stage_id` — проверяет их валидность и принадлежность
6. Применяет изменения, обновляет `updated_at`
7. Возвращает обновлённый источник

### Что решает
Позволяет скорректировать настройки источника (например, сменить воронку для webhook или состав полей публичной формы) без его пересоздания.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Источник не найден:** `404`
- **Невалидная конфигурация:** `422`

### Постусловия
- Поля `Source` обновлены

## UC-SOURCE-04: Активировать источник

**Актор:** `admin`, `director`  
**API:** `POST /api/v1/source/{id}/activate`

### Предусловия
- Источник существует и не удалён
- Источник деактивирован (`is_active = false`)

### Порядок действий

1. Система проверяет роль (`admin` или `director`); если нет — `403`
2. Загружает источник; если не найден — `404`
3. Устанавливает `is_active = true`
4. Обновляет `updated_at`
5. Возвращает `200 OK`

### Что решает
Возобновляет приём лидов через источник. Webhook начинает принимать запросы, форма становится доступной.

### Постусловия
- `Source.is_active = true`

## UC-SOURCE-05: Деактивировать источник

**Актор:** `admin`, `director`  
**API:** `POST /api/v1/source/{id}/deactivate`

### Предусловия
- Источник существует, не удалён, активен

### Порядок действий

1. Система проверяет роль; если нет — `403`
2. Загружает источник; если не найден — `404`
3. Устанавливает `is_active = false`
4. Обновляет `updated_at`
5. Возвращает `200 OK`

### Что решает
Временно отключает источник без удаления. Webhook возвращает `503 Service Unavailable` или `400`, форма выдаёт сообщение «Форма временно недоступна». Исторические лиды остаются привязанными к источнику.

### Альтернативные сценарии
- **Источник уже деактивирован:** `200 OK` (идемпотентно)

### Постусловия
- `Source.is_active = false`
- Новые лиды через этот источник не принимаются

## UC-SOURCE-06: Перегенерировать секрет webhook

**Актор:** `admin`  
**API:** `POST /api/v1/source/{id}/regenerate-webhook-secret`

### Предусловия
- Текущий пользователь — `admin`
- Источник типа `webhook`, существует и не удалён

### Порядок действий

1. Система проверяет роль; если нет — `403`
2. Загружает источник; если не найден или тип не `webhook` — `404`/`400`
3. Генерирует новый случайный `secret_token`
4. Перезаписывает `config.secret_token` новым значением
5. Обновляет `updated_at`
6. Возвращает **новый** токен в ответе (единственный раз, когда он виден)

### Что решает
Инвалидирует скомпрометированный токен мгновенно: старый токен перестаёт работать немедленно, новый действует сразу. Позволяет реагировать на утечки секрета без пересоздания источника и его конфигурации.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Источник не webhook:** `400`
- **Источник не найден:** `404`

### Постусловия
- `Source.config.secret_token` обновлён
- Все запросы со старым токеном будут отклонены

## UC-SOURCE-07: Удалить источник (Soft Delete)

**Актор:** `admin`  
**API:** `DELETE /api/v1/source/{id}`

### Предусловия
- Текущий пользователь — `admin`
- Источник существует и не удалён

### Порядок действий

1. Система проверяет роль; если нет — `403`
2. Загружает источник; если не найден — `404`
3. Устанавливает `is_deleted = true`
4. Обновляет `updated_at`
5. Возвращает `204 No Content`

### Что решает
Исключает источник из использования без потери исторических данных. Лиды, созданные через удалённый источник, сохраняют ссылку на него для корректной аналитики по источникам.

### Постусловия
- `Source.is_deleted = true`
- Источник недоступен через API списка
- Webhook и форма возвращают `404`

## UC-SOURCE-08: Принять Webhook (автосоздание лида)

**Актор:** `system` (внешняя система, anonymous)  
**API:** `POST /webhook/{source_id}`

### Предусловия
- Источник с `source_id` существует, активен (`is_active = true`), тип `webhook`
- Запрос содержит заголовок `X-Webhook-Secret: <token>`

### Порядок действий

1. Внешняя система отправляет POST с JSON-телом и заголовком `X-Webhook-Secret`
2. Система загружает `Source` по `source_id`
3. Если не найден или `is_deleted = true` — `404`
4. Если `is_active = false` — `400` («Источник деактивирован»)
5. Сравнивает `X-Webhook-Secret` с `config.secret_token`
6. Если токен неверный — `401 Unauthorized`, событие логируется
7. Применяет `config.field_mapping` к JSON-телу запроса: маппит входящие поля на поля лида (`name`, `phone`, `email`, и т.д.)
8. Валидирует обязательные поля лида (`name`, хотя бы один контакт)
9. Берёт `funnel_id` и `stage_id` из `config` (этап типа `initial`)
10. Создаёт `Lead` с `assign_to = null`, `source_id = source.id`
11. Записывает `LeadHistory` (action `created`, `user_id = null` — системное событие)
12. Создаёт уведомления для `admin` и `director` (event_type `lead_received`)
13. Возвращает `200 OK` (или `201 Created`)

### Что решает
Полностью автоматизирует приём заявок от внешних систем (сайты, боты, формы). Менеджерам не нужно вручную переносить данные — лид появляется в CRM мгновенно. Верификация токена защищает от спама и несанкционированных запросов.

### Альтернативные сценарии
- **Источник не найден:** `404`
- **Источник деактивирован:** `400`
- **Неверный токен:** `401`
- **Невалидный payload (нет имени или контакта):** `400`
- **`stage_id` в конфиге указывает на несуществующий этап:** `500` (ошибка конфигурации)

### Постусловия
- Новый `Lead` создан в воронке на `initial` этапе
- `LeadHistory` содержит запись `created`
- Уведомления отправлены admin/director

## UC-SOURCE-09: Получить публичную форму

**Актор:** `anonymous` (любой пользователь браузера)  
**API:** `GET /forms/{source_id}`

### Предусловия
- Источник типа `public_form` существует и активен

### Порядок действий

1. Браузер запрашивает страницу формы по `source_id`
2. Система загружает `Source`; если не найден, удалён или неактивен — `404`
3. Читает `config.visible_fields` — список полей для отображения
4. Читает `config.funnel_id` для контекста (не показывается пользователю)
5. Рендерит HTML-страницу формы с полями, указанными в `visible_fields`
6. Возвращает HTML без авторизации

### Что решает
Предоставляет встраиваемую форму для сайта или мессенджера. Посетитель не обязан иметь аккаунт в CRM — форма полностью публична. Конфигурация `visible_fields` позволяет кастомизировать состав полей без изменения кода.

### Альтернативные сценарии
- **Источник не найден или неактивен:** HTML-страница «Форма недоступна» (не ошибка API, а graceful страница)

### Постусловия
- Состояние не изменяется

## UC-SOURCE-10: Отправить публичную форму (создание лида)

**Актор:** `anonymous`  
**API:** `POST /forms/{source_id}/submit`

### Предусловия
- Источник типа `public_form` существует и активен

### Порядок действий

1. Пользователь заполняет форму и нажимает «Отправить»
2. Браузер отправляет POST с данными формы
3. Система загружает `Source`; если не найден или неактивен — `404`
4. Валидирует поля: `name` обязателен, хотя бы один контакт (`phone` или `email`)
5. Берёт `funnel_id` и `stage_id` из `config`
6. Создаёт `Lead` с `assign_to = null`, `source_id = source.id`
7. Записывает `LeadHistory` (action `created`, `user_id = null`)
8. Создаёт уведомления для `admin` и `director` (event_type `lead_received`)
9. Возвращает редирект или JSON `{"status": "ok"}` → фронтенд показывает страницу «Спасибо»

### Что решает
Конвертирует посетителя сайта в лид CRM без участия менеджера. Уведомление `admin`/`director` в реальном времени позволяет оперативно назначить лид на ответственного.

### Альтернативные сценарии
- **Источник неактивен:** `400` или страница «Форма недоступна»
- **Не заполнено `name`:** `422`
- **Нет ни `phone`, ни `email`:** `422`

### Постусловия
- Новый `Lead` создан
- `LeadHistory` содержит запись `created`
- Уведомления отправлены
