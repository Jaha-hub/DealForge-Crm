# Use Cases — Кастомные поля (LeadCustomField)

---

## UC-FIELD-01: Создать кастомное поле

**Актор:** `admin`, `director`  
**API:** `POST /api/v1/custom-fields/`

### Предусловия
- Текущий пользователь — `admin` или `director`
- Нет активного (не удалённого) поля с таким же `name`

### Порядок действий

1. Пользователь отправляет: `name`, `field_type`
2. Система проверяет роль; если нет — `403`
3. Валидирует `name` (непустая строка, не длиннее 512 символов)
4. Валидирует `field_type` — одно из: `text`, `number`, `date`, `time`, `select_one`, `select_many`, `boolean`
5. Проверяет уникальность `name` среди активных полей (`WHERE is_deleted = FALSE`); если занято — `409`
6. Создаёт `LeadCustomField` с `is_deleted = false`
7. Если `field_type` = `select_one` или `select_many` — поле создано, но без вариантов; варианты добавляются через `UC-ENUM-01`
8. Возвращает созданное поле (`201 Created`)

### Что решает
Позволяет адаптировать CRM под специфику бизнеса без изменения кода: добавить «Источник обращения», «Размер компании», «Дата встречи» и любые другие атрибуты. Каждый тип поля обеспечивает корректный ввод данных: число нельзя ввести в текстовое поле, дату — в числовое.

### Альтернативные сценарии
- **Нет прав:** `403`
- **`name` уже занято активным полем:** `409 Conflict`
- **Невалидный `field_type`:** `422`

### Постусловия
- `LeadCustomField` создан
- Для `select_one`/`select_many` поле неработоспособно до добавления хотя бы одного варианта (`UC-ENUM-01`)

## UC-FIELD-02: Список кастомных полей

**Актор:** Любой аутентифицированный пользователь  
**API:** `GET /api/v1/custom-fields/`

### Предусловия
- Пользователь аутентифицирован

### Порядок действий

1. Система загружает все поля, где `is_deleted = false`
2. Для каждого поля типа `select_one` или `select_many` — дополнительно загружает список вариантов (`LeadCustomFieldEnum`)
3. Возвращает список полей с их типами и вариантами

### Что решает
Предоставляет схему расширенных полей для формы карточки лида. Фронтенд динамически строит форму на основе этого списка — добавление нового поля автоматически появляется во всех карточках без деплоя.

### Альтернативные сценарии
- **Нет активных полей:** возвращает `[]`

### Постусловия
- Состояние не изменяется (read-only)

## UC-FIELD-03: Переименовать кастомное поле

**Актор:** `admin`, `director`  
**API:** `PUT /api/v1/custom-fields/{id}`

### Предусловия
- Текущий пользователь — `admin` или `director`
- Поле существует и не удалено
- Новое имя не занято другим активным полем

### Порядок действий

1. Пользователь отправляет новое `name`
2. Система проверяет роль; если нет — `403`
3. Загружает поле по `id`; если не найдено или удалено — `404`
4. Проверяет уникальность нового `name` среди активных полей, исключая текущее поле; если занято — `409`
5. Обновляет `LeadCustomField.name`
6. Обновляет `updated_at`
7. Возвращает обновлённое поле

### Что решает
Позволяет исправить ошибки в названии или переформулировать поле без пересоздания. Важно: переименование не влияет на существующие значения `LeadCustomFieldValue` — они продолжают ссылаться на то же поле через `custom_field_id`.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Поле не найдено:** `404`
- **Новое имя уже занято:** `409`

### Постусловия
- `LeadCustomField.name` обновлён
- Существующие значения у лидов не затронуты

## UC-FIELD-04: Удалить кастомное поле (Soft Delete)

**Актор:** `admin`, `director`  
**API:** `DELETE /api/v1/custom-fields/{id}`

### Предусловия
- Текущий пользователь — `admin` или `director`
- Поле существует и не удалено

### Порядок действий

1. Система проверяет роль; если нет — `403`
2. Загружает поле; если не найдено — `404`
3. Устанавливает `LeadCustomField.is_deleted = true`
4. Обновляет `updated_at`
5. Возвращает `204 No Content`

### Что решает
Убирает ненужное поле из формы карточки лида. Soft delete гарантирует, что значения (`LeadCustomFieldValue`) у существующих лидов **сохраняются** — исторические данные не теряются. Восстановление поля возможно через `UC-FIELD-05`.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Поле не найдено:** `404`
- **Поле уже удалено:** `404`

### Постусловия
- `LeadCustomField.is_deleted = true`
- Поле скрыто из формы карточки лида
- Значения `LeadCustomFieldValue` у лидов сохранены
- `name` освобождается: новое поле может получить то же имя

## UC-FIELD-05: Восстановить кастомное поле

**Актор:** `admin`  
**API:** `POST /api/v1/custom-fields/{id}/restore`

### Предусловия
- Текущий пользователь — `admin`
- Поле существует и удалено (`is_deleted = true`)
- Нет активного поля с тем же именем (иначе конфликт уникальности)

### Порядок действий

1. Система проверяет роль (`admin`); если нет — `403`
2. Загружает поле (включая удалённые); если не найдено — `404`
3. Проверяет, что `is_deleted = true`; если нет — `400`
4. Проверяет, что нет другого активного поля с таким же `name`; если есть — `409` («Уже существует активное поле с таким именем, переименуйте его перед восстановлением»)
5. Устанавливает `is_deleted = false`
6. Обновляет `updated_at`
7. Возвращает восстановлённое поле

### Что решает
Откат случайного удаления. Восстановленное поле и все его значения у лидов снова становятся видимыми в карточках.

### Альтернативные сценарии
- **Нет прав:** `403`
- **Поле не найдено:** `404`
- **Конфликт имени с активным полем:** `409`

### Постусловия
- `LeadCustomField.is_deleted = false`
- Поле снова отображается в карточке лида
- Исторические значения `LeadCustomFieldValue` снова видны
