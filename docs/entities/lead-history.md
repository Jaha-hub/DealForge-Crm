# LeadHistory — История изменений лида

**Таблица:** `lead_history`  
**Статус:** Планируется (MVP)

---

## Описание

Неизменяемый журнал всех значимых действий над лидом. Записывается автоматически при каждом изменении: смена этапа, редактирование полей, назначение менеджера и т.д. Используется для аудита и отображения timeline в карточке лида.

---

## Поля

| Поле | Тип БД | Ограничения | Описание |
|---|---|---|---|
| `id` | UUID | PK, default uuid4 | Уникальный идентификатор |
| `lead_id` | UUID | FK leads.id, NOT NULL | Лид, к которому относится событие |
| `user_id` | UUID | FK users.id, nullable | Кто совершил действие (NULL = системное событие) |
| `action` | VARCHAR(100) | NOT NULL, CHECK | Тип действия |
| `old_value` | JSONB | nullable | Состояние до изменения |
| `new_value` | JSONB | nullable | Состояние после изменения |
| `created_at` | TIMESTAMP WITH TZ | NOT NULL | Время события |

> **Нет `updated_at`**: история только пишется, никогда не редактируется.

---

## Типы действий (`action`)

| Значение | Описание | Пример `old_value` / `new_value` |
|---|---|---|
| `created` | Лид создан | `null` / `{"name": "...", "source": "webhook"}` |
| `stage_changed` | Смена этапа | `{"stage_id": "uuid", "stage_name": "Новый"}` / `{"stage_id": "uuid", "stage_name": "Переговоры"}` |
| `field_updated` | Изменение поля | `{"field": "phone", "value": "+99890..."}` / `{"field": "phone", "value": "+99891..."}` |
| `custom_field_updated` | Изменение кастомного поля | `{"field_name": "Категория", "value": "A"}` / `{"field_name": "Категория", "value": "B"}` |
| `assigned` | Назначение менеджера | `{"user_id": null}` / `{"user_id": "uuid", "name": "Иван И."}` |
| `deleted` | Soft-delete | `{"is_deleted": false}` / `{"is_deleted": true}` |
| `restored` | Восстановление | `{"is_deleted": true}` / `{"is_deleted": false}` |

---

## Бизнес-правила

- Записи **только добавляются**, никогда не изменяются и не удаляются
- `user_id = NULL` означает системное действие (например, webhook создал лид автоматически)
- История не удаляется при soft delete лида — остаётся для аудита
- Запись создаётся **в той же транзакции**, что и само изменение
- Доступна всем ролям, у которых есть доступ к лиду

---

## Связи

| Связь | Тип | Описание |
|---|---|---|
| LeadHistory.lead_id → Lead | Many-to-One | К какому лиду относится |
| LeadHistory.user_id → User | Many-to-One (nullable) | Кто совершил действие |
